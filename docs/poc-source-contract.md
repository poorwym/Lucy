# Lucy Phase 0 POC Source Contract

This contract defines the fixed input source for Phase 0. The POC does not
perform source auto-discovery: it loads one known PostGIS table from the source
config in `config/poc-sources.yaml`.

## Fixed Source

| Field | Value |
| --- | --- |
| Source id | `poc_buildings` |
| PostgreSQL schema | `public` |
| PostgreSQL table | `poc_buildings` |
| Primary id column | `id` |
| Geometry column | `geom` |
| Geometry SRID | `4326` (WGS84 longitude/latitude) |
| Source model | Extruded building footprint |
| Horizontal geometry | 2D footprint in `geom` |
| Vertical geometry | `base_height_m` plus `height_m`, in meters |
| Tile tree | 3D Tiles 1.1 implicit `QUADTREE` |
| Content format | `glb` |
| Min level | `0` |
| Max level | `16` |
| Subtree levels | `4` |
| Feature limit | `1000` features per tile |

## Sample Table Schema

The canonical fixture DDL lives in `fixtures/postgis/poc_buildings.sql`.

```sql
CREATE TABLE public.poc_buildings (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name text NOT NULL,
    building_type text NOT NULL,
    base_height_m double precision NOT NULL DEFAULT 0.0,
    height_m double precision NOT NULL CHECK (height_m > 0),
    color text NOT NULL DEFAULT '#b8b2a6',
    geom geometry(MultiPolygon, 4326) NOT NULL,
    CONSTRAINT poc_buildings_geom_valid CHECK (ST_IsValid(geom)),
    CONSTRAINT poc_buildings_geom_non_empty CHECK (NOT ST_IsEmpty(geom)),
    CONSTRAINT poc_buildings_base_height_limit CHECK (base_height_m >= 0 AND base_height_m <= 1000),
    CONSTRAINT poc_buildings_height_limit CHECK (height_m <= 500)
);
```

Required columns:

| Column | Type | Requirement |
| --- | --- | --- |
| `id` | `bigint` | Stable unique feature id. Used for feature ids and metadata. |
| `geom` | `geometry(MultiPolygon, 4326)` | Non-empty, valid WGS84 building footprint. |
| `base_height_m` | `double precision` | Optional bottom elevation of the generated mesh, in local-ground meters. Defaults to `0.0`. |
| `height_m` | `double precision` | Positive extrusion height in meters. |
| `name` | `text` | Human-readable feature name for metadata. |
| `building_type` | `text` | Coarse category for metadata. |
| `color` | `text` | `#rrggbb` material color override. |

Allowed geometry inputs for Phase 0 are `Polygon` and `MultiPolygon` footprints
with SRID `4326`. The fixture table stores normalized `MultiPolygon` values.
Curves, lines, points, geometry collections, measured coordinates, and mixed
SRIDs are out of scope.

The Phase 0 source is therefore 2.5D, not purely 2D: PostGIS provides the
horizontal footprint and explicit vertical scalars, and Lucy generates a 3D mesh
by extruding each footprint from `base_height_m` to
`base_height_m + height_m`. If `base_height_m` is omitted by incoming fixture
data, the database default is `0.0`. Full 3D source geometries such as
`PolyhedralSurfaceZ`, `TINZ`, or arbitrary solids are intentionally deferred
until the core WKB-to-mesh path exists.

## SRID and Bounds

All horizontal geometry is stored in EPSG:4326 and interpreted as
`[longitude, latitude]` coordinates in decimal degrees. Vertical values are read
from `base_height_m` and `height_m`, in meters relative to the fixture's local
ground plane. The POC does not read Z coordinates from `geom`.

The fixture is intentionally small and bounded to a San Francisco block:

```text
west:  -122.40130
south:   37.79245
east:  -122.39975
north:   37.79375
min height: 18 m
max height: 100 m
```

The POC may use these configured bounds directly. It does not need to calculate
global source bounds during startup.

For 3D Tiles bounding volumes, the configured vertical interval is:

```text
minimum z: 0 m
maximum z: 100 m
```

## WKB-to-Mesh Assumptions

Phase 0 mesh conversion accepts OGC 2D WKB `Polygon` and `MultiPolygon`
footprints from `ST_AsBinary`. EWKB type flags for Z, M, or embedded SRID are
not interpreted. Polygon interior rings, points, lines, geometry collections,
curves, and solids are intentionally unsupported until the basic footprint path
is complete.

The WKB coordinates are interpreted as EPSG:4326 `[longitude, latitude]`
decimal degrees. The internal footprint mesh projects those positions into a
local tangent meter frame centered on the configured source bounds, using an
equirectangular approximation suitable for the small POC fixture extent. Mesh
vertices are emitted as `[east_m, north_m, up_m]` with `up_m = 0.0`; extrusion
from `base_height_m` to `base_height_m + height_m` is a separate step.

## Minimal Source Config

The POC source config is `config/poc-sources.yaml`:

```yaml
sources:
  poc_buildings:
    connection: ${DATABASE_URL}
    schema: public
    table: poc_buildings
    geometry_column: geom
    id_column: id
    srid: 4326
    source_model: extruded_footprint
    vertical_reference: local_ground_meters
    base_height_column: base_height_m
    height_column: height_m
    geometry_types:
      - Polygon
      - MultiPolygon
    bounds:
      west: -122.40130
      south: 37.79245
      east: -122.39975
      north: 37.79375
      min_height_m: 0.0
      max_height_m: 100.0
    min_level: 0
    max_level: 16
    subtree_levels: 4
    max_features_per_tile: 1000
    attributes:
      - name
      - building_type
      - base_height_m
      - height_m
    material:
      color_column: color
      default_base_color: [0.72, 0.70, 0.65, 1.0]
```

Startup validation for this fixed source should check:

1. The configured schema/table exists.
2. `id_column` exists and is integer-like.
3. `geometry_column` exists, has SRID `4326`, and contains only Polygon or MultiPolygon features.
4. The configured vertical columns exist, `base_height_m` defaults to `0.0`, and `height_m > 0`.
5. The configured attributes exist.
6. A GiST index exists on `geom`.

## Loading the Fixture

Start PostGIS and load the known source:

```sh
just up
just load-poc-fixture
```

Use this database URL for local POC runs:

```sh
DATABASE_URL=postgres://lucy:lucy@localhost:5432/lucy
```

The fixture script is idempotent: it recreates `public.poc_buildings`, inserts
six features, adds the GiST index, and analyzes the table.
